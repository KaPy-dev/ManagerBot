# ManagerBot

Telegram-бот для сбора заявок (бриф) с пересылкой в чат менеджеров.

## Быстрый старт

```bash
pip install -r requirements.txt
python main.py
```

или через Docker:

```bash
docker compose up -d --build
```

## Смена бота (передача заказчику)

1. Создать бота у @BotFather, получить токен.
2. В `configuration/conf.env` заменить:
   - `TOKEN` — токен нового бота;
   - `OWNER_ID` — Telegram ID владельца (узнать через @userinfobot).
3. Юзернейм бота нигде в коде не используется — менять ничего не нужно.
4. У @BotFather боту можно включить `/setjoingroups` → Enable, чтобы его можно было добавлять в группы.
5. Добавить бота в группу/канал менеджеров и назначить администратором
   (иначе он не видит сообщения группы и не сможет писать в канал).
6. Владелец в боте: `/admin` → «📌 Чат для заявок» → выбрать группу из списка.
   ID группы руками вписывать не нужно — бот сам её регистрирует.
7. При первом запуске с чистой папкой `storage/` все настройки создаются заново.

## Конфигурация (`configuration/conf.env`)

| Переменная | Назначение |
|---|---|
| `TOKEN` | токен бота от @BotFather |
| `OWNER_ID` | Telegram ID владельца (роль передаётся только через /admin) |
| `MANAGER_CHAT_ID` | стартовый чат заявок; после запуска меняется через /admin и хранится в `storage/settings.json` |
| `API_SECRET` | секретная фраза внешнего HTTP API (заявки с сайта). Пустая — API выключен |
| `API_HOST`, `API_PORT` | адрес и порт HTTP API (по умолчанию `0.0.0.0:8090`) |

## Роли

- **Владелец** — назначает/удаляет админов, видит чаты бота, меняет чат заявок, может передать права.
- **Админ** — панель /admin, список админов, досье пользователей.

## Данные

- `storage/settings.json` — владелец, админы, чат заявок, известные чаты.
- `storage/answerbot.db` — SQLite: пользователи и история заявок (досье в /admin).
- `storage/fsm_state.json` — незавершённые опросы, восстанавливаются после рестарта.

## Внешний HTTP API (заявки с сайта)

Бот поднимает HTTP-сервер в том же процессе, что и polling (порт `API_PORT`, по умолчанию 8090).
Сайт dipled.ru шлёт через него заявки в тот же чат менеджеров, что и бриф в Telegram, тем же текстом.
Все запросы, кроме `/health`, должны нести заголовок `X-Api-Secret` с фразой из `API_SECRET`.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/v1/health` | проверка, что процесс жив (без секрета) |
| GET | `/api/v1/status` | бот, выбранный чат менеджеров, версия API |
| POST | `/api/v1/leads` | отправить заявку в чат менеджеров |

Тело `POST /api/v1/leads` (JSON, обязательны `phone` и `purchase`):

```json
{
  "lead_id": 17, "source": "сайт", "purchase": "Коммерческая",
  "mounting": "Настенный", "service": "Фронтальный", "screen_size": "300 x 200 см (Г x В)", "city": "Омск",
  "communication": null, "phone": "+7 900 123-45-67", "email": "ivan@example.com", "name": "Иван",
  "description": "Комментарий клиента", "page": "https://dipled.ru/zayavka"
}
```

Ответы: `200 {"ok": true, "chat_id": …, "message_id": …}`; `400` — неверные данные; `401` — неверный секрет;
`503` — чат заявок не выбран (владелец выбирает его через /admin); `502` — Telegram не принял сообщение.
Секрет, адрес и порт бота указываются в админке сайта (`/admin` → «Интеграция»), код сайта менять не нужно.

При переезде бота на другой сервер: открыть порт `API_PORT` для IP сайта (или спрятать API за nginx с HTTPS)
и поменять адрес в админке сайта.
